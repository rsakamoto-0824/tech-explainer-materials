アプリ開発のUIアンチパターンまとめ

「やってはいけないUI」を、悪い例（BEFORE）と改善例（AFTER）のビジュアル比較で確認できる資料です。

注記： Nielsen Norman Group・Material Design・Apple HIG など一般的なUI/UXガイドラインと、 端末のKindle書籍3冊（『UIデザイン41の法則』『UIデザインのアイデア帳』『UIデザインの教科書』）が一般に扱うテーマを参考にまとめました。 KindleはDRMで保護されているため本文の直接引用は行っていません。

1. ナビゲーション

1-1. アイコンだけで意味を示す（ミステリーミート）

アイコンしか並んでおらず、押すまで何が起きるか分からない。

アイコン＋短いテキストを併記。最低でもツールチップを用意する。

1-2. ハンバーガーメニューに主要機能まで詰め込む

「☰」の中にすべて隠してしまうと、利用率が大きく落ちる。

「見えない機能」は使われない。1タップ追加で利用率が半減することもある。

よく使う2〜5機能はタブバーやヘッダーに露出。それ以外をメニューに格納する。

1-3. 階層が深すぎる／現在地が分からない

原則3階層以内。パンくずや見出しで現在地を常に表示する。

5. 文字・コントラスト

5-1. 文字が小さく、行間が詰まりすぎ

本サービスのご利用にあたっては利用規約をよくお読みください。本サービスは18歳以上のお客様を対象としています。お問い合わせは平日10時から17時まで受け付けております。
本サービスのご利用にあたっては利用規約をよくお読みください。 18歳以上のお客様を対象としています。

本文は16px以上、行間1.5〜1.7倍を基本に。

5-2. グレー文字でコントラスト不足

パスワードは8文字以上、英数字記号を含めてください。
登録するとメルマガが届きます。
パスワードは8文字以上、英数字記号を含めてください。
登録するとメルマガが届きます。

本文は WCAG コントラスト比 4.5:1 以上。大文字でも 3:1 以上。

5-3. 本文を全部「中央揃え」にする

目的としたクラウドサービスです。

11. 参考書籍3冊の補足

各書籍が一般に扱うテーマと、本資料のアンチパターンとの対応関係を整理しました。書籍本文の直接引用は含みません。

1『UIデザイン41の法則』

位置づけ：UI/UX設計に関わる「人間の認知特性に基づく法則」のカタログ。

本資料との関係：各アンチパターンが「なぜ問題か」を、心理学・認知科学の法則で裏付ける役目。

代表的な法則意味本資料の関連項目
Fittsの法則対象が大きく近いほど素早く押せる3-4 タップ領域 / 6-2 閉じるボタン
Hickの法則選択肢が多いほど判断時間が増える1-2 ハンバーガー詰め / 3-2 主要ボタン乱立
Millerの法則短期記憶は7±2程度1-3 深い階層 / 2-4 まとめてエラー
Teslerの法則複雑さは消えず誰かが引き受ける2-3 フォーマット強制
Jakobの法則ユーザーは他サイトの慣れに沿う10-2 OS慣習
Dohertyの閾値応答400ms以内で生産性向上4-1 ローディング表示
美的ユーザビリティ効果美しいUIは使いやすく感じる5章全般

2『UIデザインのアイデア帳』

位置づけ：「悪い例 → 改善例」をビジュアルに比較する実務向けパターン集。本資料の章構成と最も相性がよい一冊。

  • フォーム改善のビフォーアフター　→　2章全般
  • ボタンの主従と配置　→　3-1、3-2
  • リスト／カードの情報密度　→　5-2、10章
  • 空状態（エンプティステート）の見せ方　→　4-2、4-3
  • 余白とグルーピング　→　5章全般
  • モーダル・ポップアップの出すタイミング　→　6章全般

3『UIデザインの教科書』

位置づけ：マルチデバイス時代のUI設計を体系的にまとめた教科書。

  • 情報アーキテクチャ（IA）／階層設計　→　1-3、10章
  • マルチデバイス（PC／スマホ／タブレット）　→　8章全般
  • ナビゲーションの種類と使い分け　→　1章全般
  • 視線誘導とグリッド・余白　→　5章、10章
  • インタラクション（遷移・アニメーション）　→　4章、6章
  • OS／プラットフォーム慣習との整合　→　10-2
