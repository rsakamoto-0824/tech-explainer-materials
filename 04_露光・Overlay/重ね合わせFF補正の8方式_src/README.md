# 重ね合わせFF補正の8方式（標準・グラレコ風・インフォグラフィック風）の生成元

## 目的

リソグラフィーの重ね合わせを制御するFF（フィードフォワード）補正の8方式を、必要な計測とプロセスフローの観点でまとめる。中身は同じで、見た目の違う3つの版を作る。

| 版 | 出力ファイル | 見た目 |
|---|---|---|
| 標準 | `../重ね合わせFF補正の8方式_計測とプロセスフロー.pptx` | 色分けした箱のフロー。和文 BIZ UDGothic |
| グラレコ風 | `../重ね合わせFF補正の8方式_グラレコ風.pptx` | 手描き風の枠・矢印、マーカーの色、蛍光ペン、手描きアイコン。和文 HG丸ｺﾞｼｯｸM-PRO |
| インフォグラフィック風 | `../重ね合わせFF補正の8方式_インフォグラフィック風.pptx` | 大きな数字、色の丸に入れたアイコン、太い線でつないだ手順。和文 BIZ UDGothic |

どの版も4枚で、全スライドに発表者ノートと出典がある。

- p.1 サマリー（A 露光機単独／B Litho Booster／C Wafer歪み計測）
- p.2 A 露光機単独（①低次 ②高次 ③推定＋高次）
- p.3 B Litho Booster（④全Shot ⑤推定＋全Shot）
- p.4 C Wafer歪み計測（⑥高次 ⑦裏面CVD ⑧NZO）

`old/` には、最初に作った1枚版の資料と生成スクリプトを残している。

## ファイル

| ファイル | 役割 |
|---|---|
| `content.js` | 3つの版で共通の中身。方式（`METHODS`）、グループ（`GROUPS`）、出典（`REFERENCES`）、ページの見出し・リード文・脚注・左パネルの事実（`PAGES`）、発表者ノート（`notesFor`）。文言を直すときはここだけ直す |
| `draw_common.js` | 共通の描画部品。線（矢印）と、計測範囲のミニ図（Wafer） |
| `build_deck.js` | 標準版を作る |
| `build_deck_grareco.js` | グラレコ風を作る（手描きの揺れは乱数の種を固定しているので、毎回同じ形になる） |
| `build_deck_infographic.js` | インフォグラフィック風を作る |
| `postprocess.py` | 和文フォントの文字セット修正、ノートマスターの正規化、DEFLATE再圧縮 |
| `check_deck.py` | 部品の実在、ノート、和文フォント、はみ出し、仮置き文字の検査 |
| `build.sh` | 生成 → 後処理 → 検査 → 正本への置き換えを順に実行 |

## 実行方法

```bash
./build.sh
```

- 引数で版を選べる: `./build.sh standard`、`./build.sh grareco`、`./build.sh infographic`（省略時は3つとも）
- 必要な環境: Node.js（pptxgenjs をグローバルに導入済み）、Python 3（python-pptx）
- 環境変数・認証情報は不要

## 注意事項

- PowerPointで出力ファイルを開いている間は再生成しない（`build.sh` はロックファイルを見つけると止まる）
- 再生成した後は、PowerPoint実機で修復ダイアログが出ないことを確認し直す
- グラレコ風の「HG丸ｺﾞｼｯｸM-PRO」は Office に同梱のフォント。Office のないパソコンや LibreOffice では別のフォントに置き換わり、文字の折り返しが変わる。確認画像（LibreOffice）は目安で、最終確認は PowerPoint で行う
- ⑧（PWGからのNZO補正）は、形状からNZOを予測する公開事例を作成時に確認できていない（ノートに明記）
- 計測点数などは代表的な目安で、装置・工程・製品で変わる
