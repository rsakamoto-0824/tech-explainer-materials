# GitHub Copilot AIクレジット節約ルール（禁止事項）

- 作成日: 2026-07-08
- 対象: GitHub Copilot（従量課金のAIクレジット制）でのPower BIダッシュボード開発
- 前提となる消費の仕組み:
  **クレジット消費 ≒ リクエスト回数 × モデル倍率 × 送受信データ量**
  会話履歴・添付ファイル・指示ファイルは毎回のリクエストで送信される。
  ※クレジットの単価・モデル倍率は変更されるため、GitHub公式の課金ページで最新を確認する。

## 1. 依頼の仕方の禁止事項

- 曖昧な依頼をしない（「いい感じにして」は禁止）。対象ファイル・期待する結果を1回で伝える
- 関連する変更を小分けに依頼しない。1つのメッセージにまとめる
- 同じ質問の言い換えや「再生成」の連打をしない。結果が違うのは依頼が曖昧なのが原因
- AIなしでできる作業を依頼しない（単純なリネーム、値の書き換え、コピー&ペースト）

## 2. 会話・コンテキストの禁止事項

- 1つのチャットで別のタスクを続けない。**タスクが変わったら新しいチャットを開く**
  （長い会話履歴は毎回まるごと送信され、後半ほど1回あたりの消費が増える）
- 大きなファイルを丸ごと添付しない（レポートJSON全体、データファイル）。
  変更対象のファイル・箇所だけを指定する
- `.pbi/cache.abf` 等のバイナリや実データをコンテキストに含めない
- 用語の意味などの一般知識の質問を高倍率モデルでしない（無料の検索やドキュメントで調べる）

## 3. モデル・機能の禁止事項

- 単純作業（書式修正・コメント追加・軽微な修正）に高倍率モデルを使わない。
  Claude Opusは設計・複雑なDAX・Deneb定義など難しい作業に限定し、
  単純作業は標準モデルに切り替えるか、AI自体を使わない
- 自動レビュー・自動生成系の機能を、全PR・全コミットで無差別に有効にしない。必要なPRだけで使う
- Copilotコーディングエージェントに、大きく曖昧なIssueを丸投げしない
  （探索と試行錯誤の分だけ消費される。Issueは小さく具体的に書く）

## 4. エージェントモードの禁止事項

- 広い指示（「リポジトリ全体を改善して」等）で放置しない
- 失敗の繰り返しを放置しない。**2回失敗したら止めて、依頼の書き方を直してから再開する**
- リポジトリ全体の走査・一括変換・一括整形をさせない

## 5. 上限と見える化（禁止事項とセットの習慣）

- **支出上限（spending limit）を必ず設定する**。設定せずに使い始めない
- 月次でクレジット消費レポートを確認し、消費の多い操作を特定して依頼の仕方を直す
- 消費が想定を超えた月は、原因（長い会話・大きな添付・エージェント放置）を特定してから使い続ける

## 補足: 指示ファイル側の対策

`.github/copilot-instructions.md`（テンプレート: `copilot-instructions-powerbi.md`）に以下を定義済み。

- 実データ・巨大ファイルを読まない
- ファイル全体を再出力せず、変更箇所だけ示す
- リポジトリ全体の走査をしない。試行錯誤を2回で打ち切り報告する
- 指示ファイル自体を短く保つ（毎回送信されるため、長いルールはそれ自体が消費になる）
