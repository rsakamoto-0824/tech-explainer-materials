2設計の起点：「3〜5の問い」を書き出す

英語動画・記事が口を揃えるのが「作り始める前に目的を言語化せよ」という点です。

最初に "key questions" を決める

優れたダッシュボードには明確なゴールがあります。英語の解説では「答えるべき3〜5個の重要な問い（key questions）を先に書き出す」ことが繰り返し推奨されます。この問いが、必要なデータの選択とデザインの判断基準になります。

英語コミュニティの定番アドバイス：「Write down the 3–5 key questions you need to answer.（答えるべき3〜5個の問いを書き出す）」 — その答えが、使うデータとデザインの選択を導く。

閲覧者のタイプで設計を変える

ダッシュボード種別閲覧者設計の方針
Executive（経営層向け）意思決定者1ページにKPIを3〜5個、タイルは5〜8個に厳選
Operational（現場向け）オペレーション担当ドリルスルー／フィルターで詳細を掘れる設計
💡 1ページ＝1つの問い

"Each report page should address one central question."＝1ページで1つの中心的な問いに答える。これは見やすさだけでなく、表示速度（パフォーマンス）の面でも有利です。

3データモデル & カレンダーディメンション

英語動画では「ダッシュボードの信頼性は土台のモデルで決まる」という前提が徹底されています。

セマンティックモデル（semantic model）を堅牢に

  • "Your final dashboard is only as reliable as the data it's built on."＝ダッシュボードの信頼性は元データの品質まで。取り込み時の余分な列・命名のゆれ・型違いを直す
  • スタースキーマ（star schema）を基本に、ファクトとディメンションを明確に分離
  • 明示的なメジャー（explicit measures）で計算を定義し、再利用可能・テスト可能にする

カレンダーディメンションは「すべての中核」

英語のDAX解説で最も強調されるのが日付テーブルです。"A good calendar dimension is the core element of every Power BI data model."（良いカレンダーディメンションはあらゆるモデルの中核）。生（なま）の日付列を使うのではなく、年・四半期・月・曜日などの属性を持つカレンダー表を作ります。

// CALENDARAUTO で日付範囲を自動生成し、属性列を追加
Calendar =
ADDCOLUMNS(
    CALENDARAUTO(),
    "Year",    FORMAT([Date], "yyyy"),
    "Month",   FORMAT([Date], "MMM"),
    "Quarter", "Q" & QUARTER([Date])
)

作成後、このカレンダー表をファクトテーブルの日付列と関連付ければ、次章の時間インテリジェンス関数が正しく動きます。

4DAXの実践テクニック（英語動画の定番5パターン）

Zebra BIやSQLBIなどが繰り返し紹介する、ダッシュボードを一段引き上げるDAXパターンです。

① メジャーを使う（インライン式を避ける）

"Move complex DAX from visual-level expressions into named measures."＝複雑な計算はビジュアル内ではなく、名前付きメジャーに切り出す。名前付きメジャーは再利用可能・テスト可能・高速です。これは英語圏で最も繰り返される鉄則。

② 変数（VAR / RETURN）で読みやすく

英語動画では VAR と RETURN を使って計算を段階分けする書き方が定番です。可読性が上がり、同じ計算の重複も防げます。

Revenue Growth % =
VAR CurrentRevenue = [Revenue AC]
VAR PriorRevenue   = [Revenue PY]
RETURN
    DIVIDE(CurrentRevenue - PriorRevenue, PriorRevenue)

③ 前年比は DATEADD が最も汎用的

"DATEADD is the most versatile and safest to work with."＝時間シフトには DATEADD が最も柔軟で安全、と紹介されます。

// 前年同期の売上
Revenue PY =
CALCULATE( [Revenue AC], DATEADD('Calendar'[Date], -1, YEAR) )

④ CALCULATE + FILTER でシナリオ別メジャー

実績（Actual）と計画（Plan）を分けるなど、条件付きの「どれだけ？」に答えるメジャーを作ります。

Revenue Actual =
CALCULATE( SUM(Sales[Amount]),
    FILTER(Sales, Sales[Scenario] = "Actual") )

⑤ SWITCH で「動的切替」（英語動画の人気テク）

切断テーブル（disconnected table）＋ SWITCH で、同じ指標を月次／年初来（YTD）で切り替える、あるいは売上／コスト／粗利をボタン1つで切り替える仕組みを、メジャーを増やさず実現します。

Selected KPI =
SWITCH( SELECTEDVALUE(KpiSelector[Id]),
    1, [Revenue],
    2, [Cost],
    3, [Gross Profit]
)
💡 1つの式に意味を詰め込みすぎない

"Break complex calculations into intermediate measures."＝複雑な計算は中間メジャーに分割。[Revenue]→[Revenue PY]→[Growth %]のように積み上げると保守性が上がります。

5レポートデザイン ― 神は細部に宿る

Guy in a Cubeなどが「report design」で語るのは、整列・グリッド・余白といった“細部の作り込み”です。

① 12カラムグリッドで整列させる

"Use a 12-column grid layout for all reports."＝全レポートを12カラムのグリッドで設計。これでPC・Web両方で視覚要素がきれいに揃います。Power BI Desktopの機能で実装できます。

  • Align / Distribute（整列・等間隔配置）：複数ビジュアルを選び、Format リボンから上下左右の整列・均等配置
  • Gridlines & Snap to grid（グリッド線・グリッドに合わせる）：View メニューからオンにし、ピクセル単位のズレを防ぐ
Guy in a Cube 系の定番Tip：整列していないだけでレポートは“素人っぽく”見える。Align・Distribute・Snap to grid を使い、ビジュアルの端をきっちり揃えるだけで完成度が一気に上がる。

② JSONテーマファイルでブランド統一

"Implement JSON theme files to enforce consistent colors, fonts, and visual defaults."＝JSONのテーマファイルで色・フォント・既定値を全社で統一。手作業で色を指定するのではなく、テーマで一元管理するのが英語圏の標準的アプローチです。

③ タイル数・数値の見せ方を絞る

  • 経営層向けはタイル5〜8個に厳選（情報の入れすぎを防ぐ）
  • 1ページ＝1つの中心的な問いに答える
  • 大きな数値は丸めて表示（"$3.4M" のように単位付きで）

④ アクセシビリティ（accessibility）も意識

色だけに頼らない（色覚に配慮）、十分なコントラスト、ビジュアルの代替テキスト（alt text）など、英語圏ではアクセシビリティが品質基準として語られます。

6インタラクティブ機能（drill / bookmark / tooltip）

Pragmatic Worksなどが "Must Know / Game Changer" として紹介する操作機能群です。

Drill Down と Drill Through の違い

Drill Down（ドリルダウン）Drill Through（ドリルスルー）
動き同じビジュアル内で階層を展開（年→四半期→月）選んだ値のフィルター文脈を保ったまま別ページへ移動
用途1つのグラフで粗→細特定の顧客・部門・地域の明細を表示

Drill Through の設定手順（英語チュートリアル準拠）

  1. Source ページ（概要）と Target ページ（詳細）の2枚を用意する
  2. Target ページのビジュアル化ペインで、フィルター列（例 ManagerName）をDrill through欄にドラッグ
  3. "Keep all filters" をオンにすると、地域やカテゴリなど元ページのフィルターも引き継がれる
  4. Source ページでデータ点を右クリック／ホバー → ドリルスルーで Target へ移動
📌 戻るボタンは自動で付く

Drill Through を設定すると、Target ページに「戻る（Back）」矢印ボタンが自動生成されます。手動で付ける場合は Insert > Buttons > Back から追加し、Action を Back に設定します。

Bookmarks（状態のスナップショット）

"A bookmark captures the current state of a report page."＝ページの現在の状態（選択・フィルター・ドリルスルー状態）を丸ごと保存。ボタンに割り当てれば、ページを増やさずに“多ページアプリ”のような切替を作れます。

Report Page Tooltips（ツールチップページ）

英語動画で人気の上級テク。通常のツールチップ（hoverで小さな情報表示）に加え、専用ページをまるごとツールチップにすることで、ホバー時にミニグラフ付きの濃い情報を見せられます。

  • File > Options > Preview features で Modern visual tooltips を有効化（再起動）
  • ツールチップ用ページを作り、ページサイズを Tooltip に設定して専用ビジュアルを配置

7パフォーマンス最適化

英語圏では「遅いレポートは使われない」と数値目標で語られます。

  • 3秒以内のロードを目指す："Optimize for sub-three-second load times." 5秒を超えると企業ユーザーは離脱する、とされる
  • 1ページのビジュアルは8個以下に：描画クエリが増えるほど遅くなる
  • 集計（aggregations）を使って大規模データの応答を速くする
  • 計算はモデル側のメジャーで事前計算（pre-calculate）し、ビジュアル内インライン式を避ける
  • 更新は業務時間外に："Schedule refresh during off-peak hours."（深夜〜早朝）でクエリ競合を避ける
  • 不要な列・テーブルは取り込まない（データ量削減が最大の高速化）

8ガバナンス & モバイル対応

「作る」だけでなく「安全に配る・どの端末でも見せる」までが英語動画の守備範囲です。

行レベルセキュリティ（Row-Level Security / RLS）

"Apply row-level security to every production dashboard."＝本番ダッシュボードには必ずRLSを適用。役割（role）ごとの静的フィルター、または USERPRINCIPALNAME() を使った動的フィルターで、ユーザーごとに見えるデータを制御します。

// 動的RLSの例：ログインユーザーの担当地域だけ表示
[Region Manager] = USERPRINCIPALNAME()

モバイルレイアウト（mobile layout）

"Design mobile layouts separately using Power BI Desktop's mobile layout editor."＝スマホ用は専用のモバイルレイアウトエディタで別途設計し、ビジュアルを縦に積む。PC用をそのまま縮小するのではなく、端末に合わせて作り分けます。

運用の自動化

  • 自動ページ更新（automatic page refresh）：サポートキュー・IoT・受注などの準リアルタイム表示に
  • テーマファイル・命名規則・バージョン管理でチーム運用を標準化
⚠ 機密データ・社外共有は要相談

個人情報や会員情報など、漏れると致命的なデータを扱う場合や社外公開の判断が必要な場合は、自己判断せず社内のエンジニア／管理者に相談してください。RLSと共有範囲は公開前に必ず確認しましょう。
