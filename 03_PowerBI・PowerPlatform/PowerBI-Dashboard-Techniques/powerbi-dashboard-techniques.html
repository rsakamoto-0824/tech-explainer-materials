Power BI ダッシュボード作成技術 総まとめ
― 日本語解説動画から学ぶ実践テクニック ―

YouTube上のPower BI日本語解説動画・関連解説記事を調査し、ダッシュボード作成に必要な技術を「データ取得 → 整形 → モデリング → DAX → ビジュアル → デザイン → 共有」の流れで体系的にまとめたレポートです。

📅 作成日：2026年6月24日 🎯 対象：Power BI初心者〜中級者 🛠 ツール：Power BI Desktop / Power BI サービス

0はじめに・調査方法

本レポートの目的と、どのように情報を集めたかを説明します。

このレポートでわかること

Power BIで「見やすく・使える」ダッシュボードを作るための技術を、初心者でも順番に追えるようにまとめています。専門用語が出てきても、その都度かみ砕いて説明します。

調査方法

YouTubeでPower BIを解説している日本語動画（初心者向けダッシュボード作成、DAX・メジャー解説、ドリルスルー／ブックマークなどの機能解説）を中心に検索し、各動画のテーマと、それを補足する日本語解説記事・Microsoft公式ドキュメントを突き合わせて技術を抽出しました。参照した動画・資料の一覧は第12章にまとめています。

📌 用語の整理：「レポート」と「ダッシュボード」は別物

Power BIでは2つの言葉を厳密に使い分けます。レポートはPower BI Desktopで作る複数ページのグラフ集。ダッシュボードはWeb版（Power BIサービス）でレポートのグラフを「ピン留め」して1画面にまとめたもの、を指します。本レポートでは、作成作業全体を広く「ダッシュボード作成」と呼びつつ、必要な箇所で両者を区別します。

2つの編集画面（ビュー）を行き来する

Power BI Desktopには、作業内容に応じて切り替える3つのビューがあります。動画ではこの切り替えが頻繁に出てきます。

ビュー役割主にやること

💡 動画が口を揃えて言うこと

「グラフを作る前に、データの整形とモデリングを先に終わらせる」のが成功の鍵。土台が整っていないと、後からグラフが正しい数字を出さず、やり直しになります。

2STEP1：データの取得

分析の出発点。さまざまな場所にあるデータをPower BIに読み込みます。

操作の基本

ホームタブの「データを取得」から、読み込みたいデータの種類を選びます。Excel・CSVといった身近なファイルから、SQL Server・Oracle・MySQLなどのデータベース、クラウドサービスまで幅広く対応しています。

2つの接続モード（重要）

モード仕組み向いている場面
インポートデータをPower BI内部に取り込んで保持。動作が速い。多くのケースの既定。中〜小規模データ。
DirectQuery取り込まず、元のDBへ都度問い合わせ。常に最新。大規模・リアルタイム性が必要な場合。
📌 はじめは「インポート」でOK

動作が速く、DAXの全機能が使えるインポートが基本。「データが大きすぎる」「常に最新でないと困る」といった明確な理由が出てきたときにDirectQueryを検討します。

3STEP2：Power Queryでデータを整形する

取り込んだ「生（なま）のデータ」を、分析できるきれいな表に変える工程（ETL）です。地味ですが最重要工程の一つ。

Power Queryとは

「データの変換」ボタンから開く専用エディタです。ここで行った操作は「適用したステップ」として上から順に記録され、次回データ更新時にも自動で同じ加工が再現されます。手作業のExcel加工と違い、何度でも再利用できるのが強みです。

よく使う整形操作

  • 不要な列・行の削除：分析に使わない列は早めに消す（後述のとおりパフォーマンスにも効く）
  • データ型の設定：日付は日付型、金額は数値型に。型が違うと計算やグラフが崩れる
  • 欠損・重複のチェックとクリーニング：空白や重複行を取り除く
  • 列の分割・結合・置換：「2026/06/24」を年・月・日に分けるなど
  • クエリのマージ／追加：複数の表を横に結合（マージ）／縦に積む（追加）

整形の順番のコツ（パフォーマンス）

💡 「軽くしてから重い処理」

フィルターや列削除などデータを減らす操作を先に、マージなど重い操作を後に回すと処理が速くなります。また、環境やファイルパスが変わりうる箇所はパラメーターにしておくと使い回しがききます。

4STEP3：データモデリング（スタースキーマ）

複数の表を「関連付け」して、分析しやすい構造を作る工程。Power BIの実力はここで決まると言っても過言ではありません。

スタースキーマ（星型）が基本形

中心にファクトテーブル、その周りにディメンションテーブルを配置し、星のような形にする設計手法です。Power BIが最も得意とする構造で、多くの解説動画・公式ガイドが推奨しています。

テーブルの種類持つ情報具体例
ファクトテーブル
（中心）		ビジネスの「数値・実績」。集計の対象になる測定値。売上、利益、注文数、数量
ディメンションテーブル
（周辺）		数値を「切り口」で分けるための属性情報。商品マスタ、顧客マスタ、店舗マスタ、日付マスタ

スタースキーマのメリット

  • クエリが速くなる：ファクトとディメンションを分離することで集計効率が上がる
  • DAX（メジャー）が書きやすい：シンプルな構造なので計算式が複雑になりにくい
  • 分析の自由度が高い：商品別・地域別・期間別など多角的に切り替えやすい
  • メンテナンスが楽：構造が単純で、追加・変更がしやすい

リレーションシップ設計の注意点

  • 1つのテーブルに「ファクト」と「ディメンション」の役割を混在させない
  • 関係は「多 対 一」（ファクトの多 → ディメンションの一）が基本
  • 方向はできるだけ単方向（一方向）に。双方向はループや予期せぬ集計の原因になりやすい
  • ファクトテーブルは常に同じ粒度（細かさ）でデータを読み込む

日付テーブル（カレンダーテーブル）は必ず用意する

📌 「前年比」「累計」を出したいなら必須

後述の時間インテリジェンス関数（前年比・累計など）を正しく動かすには、専用の日付テーブルが必要です。連続した日付を持つマスタを用意し、ファクトテーブルの日付列と関連付けます。CALENDARAUTO() 等のDAXで自動生成もできます。

5STEP4：DAXとメジャーで指標を計算する

「前年比」「累計」「達成率」など、元データに無い指標を自分で計算で作る仕組みです。ダッシュボードの中身の濃さはここで決まります。

DAXとは

DAX（Data Analysis Expressions）は、Power BIで集計や条件付き計算を行うための式言語です。Excelの数式に似ているため、Excel経験者は比較的入りやすいとされます。基本ルールは次のとおり。

  • 式は=から始める
  • 列の参照はテーブル名[列名]の形で書く（例：売上[金額]）
  • メジャーは「新しいメジャー」ボタンから作成する

メジャー と 計算列 の違い（最重要ポイント）

メジャー計算列
計算のタイミンググラフを見る瞬間に集計（動的）データ更新時に1行ずつ計算して保存
メモリ消費軽い（結果を保存しない）重い（列として保存され膨らむ）
使いどころ合計・平均・比率など集計値（基本こちら）行ごとの分類ラベルなど、どうしても列が要る時
⚠ 計算列の多用は避ける

計算列を増やすとモデルのサイズが肥大化し、動作が重くなります。「迷ったらメジャー」が定石です。

コンテキスト（文脈）という考え方

DAX理解の山場がコンテキストです。同じメジャーでも「どのグラフの、どの行・どのフィルターの中で計算されるか」で結果が変わります。CALCULATE や FILTER はこの文脈を意図的に操作する関数で、ここを理解すると一気に表現力が上がります。

よく使うDAX関数

分類関数用途
基本集計SUM AVERAGE MIN MAX合計・平均・最小・最大
件数COUNT DISTINCTCOUNT件数／重複を除いた件数
条件付き集計CALCULATE FILTER ALL条件を付けて集計／フィルター無視
条件分岐IF SWITCH2択／多択の分岐
割り算DIVIDE0除算エラーを防ぐ安全な割り算
リレーション参照RELATED関連テーブルの値を引っ張る
スライサー値取得SELECTEDVALUE選択中の値を取得
時間インテリジェンスDATESYTD SAMEPERIODLASTYEAR DATEADD PREVIOUSMONTH累計・前年同期・期間シフト

具体例：実務でよく作るメジャー

① 売上合計

// シンプルな合計
売上合計 = SUM(売上[金額])

② 条件付き集計（2023年だけの売上）

2023年売上 = CALCULATE(
    SUM(売上[金額]),
    売上[年] = 2023
)

③ ユーザー数（重複を除いたカウント）

ユーザー数 = DISTINCTCOUNT(アクセス[ユーザーID])

④ 前年同期比（時間インテリジェンス）

// 前年の同じ期間の売上
前年売上 = CALCULATE(
    [売上合計],
    SAMEPERIODLASTYEAR(日付[日付])
)

// 前年比（0除算を防ぐDIVIDE）
前年比 = DIVIDE(
    [売上合計] - [前年売上],
    [前年売上]
)

⑤ 累計（年初来：YTD）

売上累計YTD = CALCULATE(
    [売上合計],
    DATESYTD(日付[日付])
)
💡 複雑な式は「中間メジャー」に分ける

いきなり長い式を書かず、[売上合計]→[前年売上]→[前年比]のように段階的に積み上げると、読みやすく保守しやすくなります。

6STEP5：ビジュアル（グラフ）を選ぶ・作る

「何を伝えたいか」でグラフの種類を選びます。データに合わないグラフは誤解を生みます。

KPIカードの作り方（最頻出）

ダッシュボード最上部に置く「重要数値を大きく見せるカード」の作り方です。

  1. レポートビュー右の「視覚化」から「カード」を選択
  2. 表示したい指標（多くはメジャー）をドラッグ＆ドロップ
  3. 「ビジュアルの書式設定」で色・フォント・形状を調整
  4. ％表示にしたい場合は書式設定の「％」を適用

例えばユーザー数のカードなら、まずユーザー数 = DISTINCTCOUNT(...)のメジャーを作り、それをカードに乗せます。前週比などの増減指標を添えると一目で状況が伝わります。

グラフ選びの早見表

伝えたいこと適したグラフ備考
大きさの比較横棒／縦棒グラフ人が最も正確に比較できる
時間の推移折れ線グラフトレンドを見せる
全体に占める割合円グラフ（カテゴリ8個未満）多用は禁物。比較には不向き
目標に対する達成度ゲージグラフ現状と目標の関係を表示
重要な単一の数値カード／KPIビジュアルダッシュボードの主役
2項目の相関散布図分布・傾向を見る
⚠ 避けたいグラフ・表現（公式ガイドより）
  • 3Dグラフ：奥行きで値が歪み読み取りづらい
  • 円・ドーナツ・ゲージの多用：細かい比較には向かない
  • 大小の差が極端なメジャーを同じ軸に混ぜない（必要なら第2軸を使う）
  • 不要なデータラベルは消す（棒グラフは長さで十分伝わる）

7STEP6：ダッシュボードのデザイン原則

「見やすく・使える」ダッシュボードにするための、配色・レイアウト・情報設計のルールです。

① 閲覧者と目的を最初に決める

  • 誰が、どんな意思決定のために見るのか
  • その判断に必要な「主要メトリック」は何か
  • PC・タブレット・スマホ、どの画面で見るのか（画面が小さいほどタイルは絞る）

② 1画面でストーリーを語る

  • 重要情報はひと目で。スクロールなしで収めるのが理想
  • 情報を詰め込みすぎない。必須でないものは削る
  • 提供時は全画面表示モードで余計な要素を排除

③ 視線の流れに沿って配置する

人は左上から右下へ読みます。最上位の概要（KPIカード）を左上に置き、右・下へ進むほど詳細になるよう配置すると自然に読めます。全体俯瞰 → セグメント別 → 個別データの順でストーリー性を持たせます。

④ 配色は絞る

  • 基本色＋アクセント色を2〜3色程度に制限
  • ブランドカラー（テーマカラー）を一貫して使い統一感を出す
  • 強調したい指標だけアクセント色で目立たせる
  • 同じ項目には同じ色を使う（グラフ間で色の意味を揃える）

⑤ レイアウトと余白

  • 適度な余白で視線を誘導する。要素を詰め込みすぎない
  • 同じ種類の情報は近くにグルーピング
  • 概要ページ・詳細ページにページを分割するのも有効

⑥ 文字・数値の見せ方

  • フォントのサイズ・種類を統一（バラつくと目がちらつく）
  • 大きな数値は3〜4桁に丸める。「3,400,000」より「340万」が読みやすい
  • 時間の粒度・期間をグラフ間でそろえる（先月と特定月を並べない）
  • 同じテイストのアイコンで洗練度を上げる
💡 デザインの土台「ゲシュタルト原則」

近接・整列・類似などの視覚認知の原則を知ると、説得力のある配置が作れます。Stephen Few『Information Dashboard Design』、Edward Tufte『Envisioning Information』などが公式に推薦されています。

8STEP7：インタラクティブ機能で「使える」化

Power BIの真価は、見る人が自分で操作して深掘りできる点にあります。動画でも人気の機能群です。

スライサー（フィルター部品）

期間・地域・商品などを選んで、画面全体のグラフを一斉に絞り込む部品です。日付スライサーで「今週」を動的に選ばせる、といった設計もよく使われます。

ドリルダウン と ドリルスルー の違い

ドリルダウンドリルスルー
動き同じグラフ内で階層を掘り下げる（年→四半期→月）選んだ値を条件に別ページへ移動して詳細表示
用途1つのグラフで粗→細を見る特定の顧客・商品・地域の明細を見る
準備軸に階層を設定するだけ「概要ページ」と「詳細ページ」の2枚を用意し、詳細ページにドリルスルー列を設定

ブックマーク（状態の記録・再現）

スライサーやフィルターの状態をまるごと記録して、ワンクリックで再現する機能です。代表的な活用が「フィルターを一発で解除するボタン」。ワークフローは次の3ステップ。

  1. ボタンを用意する
  2. 見せたい操作・状態を作ってブックマークに記録する
  3. 記録した内容をボタンに割り当てる

ボタンアクション

ボタンにブックマークやドリルスルーを割り当てると、複雑なスライサー操作なしで「ある視点のデータをワンクリックで表示」できます。ナビゲーション付きの本格的なインタラクティブレポートが作れます。

💡 機能の組み合わせが上級者への近道

「ボタン＋ブックマーク」「ボタン＋ドリルスルー」のように組み合わせると、まるでアプリのように操作できるダッシュボードになります。

9STEP8：公開・共有・運用

作って終わりではなく、関係者に届け、最新に保ち続ける工程です。

レポートの公開とダッシュボード化

Power BI Desktopで作ったレポートをPower BIサービス（Web）に公開すると、ブラウザやモバイルから閲覧できます。サービス上で各グラフにマウスを乗せ、ピン（📌）アイコンを押すとダッシュボードにタイルとしてピン留めできます。複数レポートの要点を1枚に集約するイメージです。

運用・ガバナンスのポイント

  • 自動更新：Power BIサービスのスケジュール更新や、社内DB接続用のオンプレミスデータゲートウェイで定期更新を設定
  • アクセス管理：ロールベースで「誰がどのデータを見られるか」を制御し、共有ポリシーを定める
  • バージョン管理：変更履歴をGitやTeamsなどで追えるようにする
⚠ 社外公開・機密データの取り扱いは要注意

会員情報・個人情報など漏れると致命的なデータを扱う場合や、社外公開の判断が必要な場合は、自己判断で進めず社内のエンジニア／管理者に相談してください。アクセス権限と公開範囲は必ず確認しましょう。

10パフォーマンス最適化のベストプラクティス

「重くて使われないダッシュボード」を避けるための、横断的なコツをまとめます。

  • 不要な列・テーブルは取り込まない：データ量を減らすことが最大の高速化
  • スタースキーマを徹底：複雑なリレーションは遅さの原因
  • 計算列よりメジャー：モデルの肥大化を防ぐ
  • 双方向リレーションを避ける：単方向を基本にしてループを作らない
  • Power Queryは「軽い処理を先、重い処理を後」
  • ビジュアルを1ページに詰め込みすぎない：表示するグラフが多いほど描画が遅い
  • 日付テーブルを用意：時間インテリジェンスを効率よく動かす

11完成前チェックリスト

ダッシュボードを公開する前に、このリストで自己点検しましょう。

データ・モデル

  • 不要な列・行を削除し、データ型を正しく設定したか
  • スタースキーマ（ファクト＋ディメンション）になっているか
  • リレーションは「多対一・単方向」が基本になっているか
  • 日付テーブルを用意し、ファクトと関連付けたか

計算（DAX）

  • 集計は計算列でなくメジャーで作っているか
  • 割り算はDIVIDEで0除算対策をしているか
  • 前年比・累計などが正しい数字を返すか確認したか

デザイン・ビジュアル

  • 重要KPIを左上に置き、視線の流れに沿っているか
  • 1画面に収まり、スクロールなしで要点が見えるか
  • 配色は2〜3色に絞り、同じ意味に同じ色を使っているか
