VS Code 3拡張 実践ガイド

GitLens・Project Manager・Data Wrangler の3つを、はじめて使う人が最短で使いこなすための資料です。 「何ができるか」ではなく「まず何を触り、どこでつまずき、どう直すか」を中心にまとめています。

対象バージョン
GitLens 19.1.0 ／ Project Manager 13.1.0 ／ Data Wrangler 1.24.2
確認環境
macOS 26.6.2 ／ Apple M1 ／ メモリ 8 GB
キー表記
⌘ = Command、⌥ = Option、⇧ = Shift
本資料の根拠
各拡張の定義ファイル（package.json）から、コマンド名・設定キー・既定値・ショートカットを直接取得

0. 3つの役割を先に押さえる

この3つは守備範囲がまったく違います。「どれを開けばよいか」を一言で覚えてしまうのが最短です。

GitLens

答えてくれる問い

「この1行、誰がいつ何のために変えた？」

コードを読むときに使う。書く前・コミット前の確認が主戦場。

Project Manager

答えてくれる問い

「あのリポジトリ、どこだっけ？」

作業を始めるときに使う。38個のリポジトリを数キーで行き来する。

Data Wrangler

答えてくれる問い

「このデータ、そもそもどうなってる？」

解析を書く前に使う。中身を見て、前処理コードを作らせる。

✅覚え方

開くとき=Project Manager、読むとき=GitLens、データを見るとき=Data Wrangler。この3語だけ覚えれば、あとは必要になったときにこの資料へ戻れば足ります。

GitLens 1. コードの履歴をその場で読む v19.1.0

1-1 インストールすると何が変わるか

設定を何もしなくても、次の3つが自動で有効になります（すべて既定でオン）。

既定でオンになる表示
表示される場所内容対応する設定キー
カーソルがある行の右端「作者・どれくらい前・コミットメッセージ」が薄い文字で出るgitlens.currentLine.enabled
関数やクラスの上「何人が編集・最終更新はいつ」の小さなリンク（CodeLens）gitlens.codeLens.enabled
画面下のステータスバー現在行のコミット情報gitlens.statusBar.enabled
⚠️最初に知っておくべきこと

GitLens には コマンドが1,160個、設定項目が463個あります。全部覚えようとすると必ず挫折します。この資料では、実務で効く3機能だけに絞ります。

1-2 最初の1週間はこの3つだけ

  1. 行内表示を読む（操作なし）
    コードの行をクリックするだけで、その行の右端に「誰が・いつ」が出ます。これがGitLensの本体で、他は補助です。
  2. ホバーで詳細を見る
    その薄い文字にマウスを乗せると、コミットメッセージ全文と、その行が変わった差分がポップアップします。クリック不要です。
  3. ファイルの履歴をたどる
    ⌘+⇧+P でコマンドパレットを開き GitLens: Show File History を実行。そのファイルが「いつ・何のために」変わってきたかが時系列で並びます。
💡この環境での使いどころ

Claude Code や Codex に書かせたコードを後から読むとき、行にカーソルを置けば「いつ・どの依頼で入った変更か」が即わかります。コミット前に Show File History を開き、意図した差分だけが入っているかを確認する習慣をつけると、無関係な変更の混入を防げます。

1-3 慣れてきたら使う機能

次の一歩（コマンドパレットから実行）
やりたいことコマンドひとこと
ブランチの分岐を絵で見るGitLens: Show Commit Graph既定では画面下のパネルに開く
1行の履歴だけを追うGitLens: Show Line History Viewファイル全体より対象が絞れる
コミットを検索するGitLens: Search Commitsメッセージ・作者・ファイル名で探せる
直前リビジョンとの差分⇧+⌥+,ショートカットが割り当て済み
2つのブランチを比べるGitLens: Compare References...PR前の確認に
GitHubの該当行を開くGitLens: Open File on Remote共有リンクを作るとき

1-4 つまずきポイントと対処

よくある困りごと
症状原因対処
行末の表示がうるさい／気が散る 行内表示が既定でオン 常時オフにするなら "gitlens.currentLine.enabled": false。必要なときだけ GitLens: Toggle Line Blame で出す
関数の上の小さい文字が邪魔 CodeLens が既定でオン "gitlens.codeLens.enabled": false。または GitLens: Toggle Git CodeLens で一時的に消す
「3日前」ではなく日付で見たい 既定が相対表示（relative） "gitlens.defaultDateStyle": "absolute" と defaultDateFormat を設定（下の設定例を参照）
サインアップやProへの誘導が出る Launchpad / Cloud Patches / Cloud Workspaces / Worktrees は有料（Pro）機能 日常で使う3機能は無料。誘導は無視して問題ない。表示を減らすなら該当ビューを右クリックして非表示にする
導入済みの Git Graph と役割が混ざる 名前が似ているが別物 Git Graph＝ブランチ全体の俯瞰、GitLens＝1行単位の追跡。役割が重ならないので併用してよい
アイコン画像の読み込みが気になる アバター表示が既定でオン "gitlens.blame.avatars": false で画像取得をやめられる

1-5 おすすめの初期設定

まずは表示を減らして、日付を絶対表記にするところから始めるのが挫折しにくい設定です。日付形式は計測データの記録形式（yyyy/mm/dd hh:mm:ss）に合わせています。

{
  // 行内表示は残す（GitLensの本体なので）
  "gitlens.currentLine.enabled": true,

  // 関数上のCodeLensは最初はオフ。慣れたら true に戻す
  "gitlens.codeLens.enabled": false,

  // 「3日前」ではなく日付で表示する
  "gitlens.defaultDateStyle": "absolute",
  "gitlens.defaultDateFormat": "YYYY/MM/DD HH:mm",

  // アバター画像を取りに行かない
  "gitlens.blame.avatars": false,

  // 画面下のステータスバー表示は便利なので残す
  "gitlens.statusBar.enabled": true
}

Project Manager 2. リポジトリを数キーで行き来する v13.1.0

2-1 初回だけ必要な設定

この拡張は設定を1回入れるまで何も起きません。ここが最初の関門です。2つのGitHubフォルダを登録すると、配下のリポジトリが自動で一覧に集まります。

{
  "projectManager.git.baseFolders": [
    "/Users/sakamoto/04_プログラミング/ClaudeCode/GitHub",
    "/Users/sakamoto/04_プログラミング/Codex/GitHub"
  ],

  // 探索の深さ。既定は4だが、この構成は「フォルダ/リポジトリ名」の1階層なので2で十分（速い）
  "projectManager.git.maxDepthRecursion": 2,

  // 一覧をフォルダごとにまとめて表示する
  "projectManager.groupList": true,
  "projectManager.sortList": "Name",

  // 現在開いているプロジェクト名を画面下に出す（迷子防止）
  "projectManager.showProjectNameInStatusBar": true
}

⚠️設定名の落とし穴

この拡張には projectManager.openInCurrentWindowIfEmpty と、t が抜けた旧名 openInCurrenWindowIfEmpty の両方が存在します。設定画面の候補から選べば間違いませんが、手打ちするときは正しい綴りの方を使ってください。

2-2 毎日の使い方

  1. ⌘+⌥+P を押す
    登録済みプロジェクトの一覧が開きます。これが唯一覚えるべきショートカットです。
  2. 数文字だけ打つ
    「litho」「wafer」など、リポジトリ名の一部で絞り込めます。フルパスでも検索したい場合は projectManager.filterOnFullPath を有効に。
  3. Enter で切り替え
    別ウィンドウで開きたいときは、コマンドパレットから Project Manager: List Projects to Open in New Window を使います。
  4. よく使うものを登録する
    コマンドパレットで Project Manager: Save Project。名前を付けて「お気に入り」に入り、一覧の上位に固定されます。

2-3 リポジトリが増えてきたら：タグで分ける

38個あるとタグ分けが効いてきます。既定のタグは ["Personal", "Work"] ですが、運用に合わせて書き換えられます。

{
  "projectManager.tags": ["ClaudeCode", "Codex", "PowerBI", "計測解析", "アーカイブ"]
}

タグを付けたら、コマンドパレットの Project Manager: Filter Projects by Tag で絞り込めます。サイドバーの Project Manager アイコンからも同じ操作ができます。

2-4 つまずきポイントと対処

よくある困りごと
症状原因対処
設定したのに一覧が空登録直後は再スキャンが必要コマンドパレットで Project Manager: Refresh Git Projects を実行
いま開いているプロジェクトが一覧に出ないremoveCurrentProjectFromList が既定 true仕様。表示したいなら false にする
一覧が多すぎて選べない38個が平坦に並んでいるgroupList: true でまとめる／タグで絞る／よく使うものを Save Project でお気に入りに
開いたら今の作業ウィンドウが置き換わった既定では同じウィンドウで開く場合がある新ウィンドウ用のコマンド（List Projects to Open in New Window）を使う
一覧の表示が遅い探索の深さが既定4で、無関係な階層まで潜っているmaxDepthRecursion を2に下げる。git.ignoredFolders に除外フォルダを追加
削除したフォルダが残っているキャッシュに残存checkInvalidPathsBeforeListing は既定で有効。Project Manager: Edit Projects で手動編集もできる
✅効果が一番大きい使い方

「親フォルダを丸ごと開いて作業する」のをやめて、常にリポジトリ単位で開くようにすると、別プロジェクトの一時ファイルを取り違える事故がなくなります。AIエージェントのセッションも用件ごとに分かれて管理しやすくなります。

Data Wrangler 3. データの中身を見てから解析を書く v1.24.2

3-1 動かす前に必要なもの（最大のつまずき箇所）

🛑これが無いと起動しません
  • Python環境と、その環境に入った pandas
  • Jupyter拡張（導入済み）

初回起動時に「カーネルを選んでください」と聞かれます。ここでpandasが入っている環境を選んでください。選び直したいときはコマンドパレットで Data Wrangler: Change Kernel です。

3-2 開けるファイル形式

既定ですべて有効になっています。Excelがそのまま開けるのは見落とされがちな利点です。

.csv.tsv.parquet .xlsx.xls.jsonl

3-3 開き方は3通り

  1. ファイルを右クリック → Open in Data Wrangler（いちばん簡単）
  2. コマンドパレット → Data Wrangler: Open File in Data Wrangler
  3. Notebook から → 表示された DataFrame の横のボタン、または変数ビューから起動

3-4 画面の見方と操作の流れ

画面の構成
場所見えるもの
各列の見出しの下列ごとの分布・欠損数・データ型（既定で自動表示）。ここを最初に見る
中央のグリッドデータ本体。列幅の既定は200px
右側のパネル操作メニュー（欠損処理・フィルタ・並べ替え・型変換・数式など）
下部操作に対応して自動生成された pandas コード

操作は「試す → 確定 or 取り消し」の繰り返し

キー動作
⇧+Enterプレビュー中の操作を確定する
Escプレビュー中の操作を破棄する
⌘+Z確定済みの操作を1つ戻す
⌘+I自然言語で操作を指示する入力欄を出す
✅安心してよい点：元ファイルは変わりません

Data Wrangler の操作は非破壊です。元のCSVやExcelは書き換わりません。右上の「Export to notebook」でpandasコードを取り出し、自分で実行して初めて結果が反映されます。安心して色々試してください。

3-5 計測CSVでの実例

オーバーレイ計測のエクスポート（WaferId・計測日時・Shot座標・Mark座標・計測値X/Y）を点検する流れです。解析スクリプトを書く前のデータ把握に使います。

  1. 欠損と型を見る
    列見出しの下の要約で、計測値X・Yに欠損がないか、座標が数値型として読めているかを最初に確認します。文字列として読まれていると解析で必ず詰まります。
  2. ウェハ半径の列を作る
    数式（Formula）で r = sqrt(x**2 + y**2) に相当する列を追加し、有効範囲（150 mm未満）の外にどれだけ点があるかを見ます。
  3. 重複を数える
    WaferId・計測日時・Shot座標・Mark座標でグループ化し、件数が2以上の組み合わせがあるかを確認します。重複があれば平均処理が必要だと分かります。
  4. コードを取り出す
    「Export to notebook」で pandas コードを取り出し、解析スクリプトの前処理部分に取り込みます。画面操作が再現可能な手順として残るのがこの拡張の要点です。

3-6 つまずきポイントと対処

よくある困りごと
症状原因対処
開こうとするとカーネル選択が出る／失敗するpandas が入った Python 環境が選ばれていない対象の環境に pandas を入れる。Data Wrangler: Change Kernel で選び直す
動作が重い・固まるメモリ8GBに対してファイルが大きい先に列を絞る。dataWrangler.experiments.fastCsvParsing を有効にして様子を見る
区切り文字が違うCSVが崩れる自動判定が既定でオフdataWrangler.experiments.autoDetectCsvDelimiter を有効にする
NumPy配列やPolarsのデータが開けない対応型が既定でオフ（pandas の DataFrame / Series のみ既定オン）dataWrangler.outputRenderer.enabledTypes で必要な型を有効化
Notebook の出力から直接開きたい出力レンダラーが既定でオフ"dataWrangler.outputRenderer.enabled": true
列が狭くて読めない既定の列幅が200pxdataWrangler.grid.defaultColumnWidth を広げる
操作を間違えた—⌘+Z で戻せる。元ファイルは変わらないので慌てなくてよい
💡使い始めの練習に

コマンドパレットの Data Wrangler: Open Walkthrough に、サンプルデータを使った練習用ガイドが入っています。手元のデータでいきなり試すより安全です。

4. 3つを組み合わせた1日の流れ

それぞれ単独でも役立ちますが、下の順番でつなぐと「探す・確かめる・任せる・検証する」が一本の線になります。

典型的な作業の流れ
場面使うものやること
① 作業開始Project Manager⌘+⌥+P で対象リポジトリを開く。他のリポジトリのファイルを混ぜない
② データ確認Data WranglerCSV/Excelを開き、欠損・型・外れ値を把握。前処理コードを Export
③ 実装Claude Code / Codex把握した内容をもとに実装を依頼する
④ 検証GitLens行内表示とファイル履歴で、入った変更を1行ずつ確認。意図しない差分がないかを見る
⑤ 提出GitHub Pull RequestsPRを作成し、差分を読んでマージ
⚠️順番を守る理由

②を飛ばして実装に入ると、「データがそうなっていると思い込んだまま書かれたコード」ができあがります。列の型や欠損は、先に目で見て確かめるほうが結果的に速く終わります。

5. 設定まとめ（コピペ用）

ここまでの推奨設定を1つにまとめたものです。VS Code のコマンドパレットで Preferences: Open User Settings (JSON) を開き、いちばん外側の { } の中に貼り付けてください。既にある設定と重複する行があれば、そちらを優先して調整します。

  // ===== GitLens =====
  "gitlens.currentLine.enabled": true,
  "gitlens.codeLens.enabled": false,
  "gitlens.defaultDateStyle": "absolute",
  "gitlens.defaultDateFormat": "YYYY/MM/DD HH:mm",
  "gitlens.blame.avatars": false,
  "gitlens.statusBar.enabled": true,

  // ===== Project Manager =====
  "projectManager.git.baseFolders": [
    "/Users/sakamoto/04_プログラミング/ClaudeCode/GitHub",
    "/Users/sakamoto/04_プログラミング/Codex/GitHub"
  ],
  "projectManager.git.maxDepthRecursion": 2,
  "projectManager.groupList": true,
  "projectManager.sortList": "Name",
  "projectManager.showProjectNameInStatusBar": true,
  "projectManager.tags": ["ClaudeCode", "Codex", "PowerBI", "計測解析", "アーカイブ"],

  // ===== Data Wrangler =====
  "dataWrangler.columnInsights.displayOnOpen": true,
  "dataWrangler.grid.defaultColumnWidth": 240,
  "dataWrangler.experiments.autoDetectCsvDelimiter": true

💡設定後にやること

Project Manager の設定を入れたら、コマンドパレットで Project Manager: Refresh Git Projects を1回実行してください。これをしないと一覧が空のままです。
