0. 調査方法と選定基準

2. Office文書 — いちばん大きな穴

🛑今回の調査で見つかった最重要の発見

Excel・Word・PowerPoint を扱うスキルは、Claude Code 側にはプラグインとして存在しますが、Codex 側には存在しません。実際、Codex のシステム同梱スキルは imagegen / openai-docs / plugin-creator / review-agent / skill-creator / skill-installer の6件のみで、Office文書系は含まれていません。

つまり、同じ「資料を作って」という依頼でも、Codex では実行できない状態です。共有スキルフォルダに入れれば、両方で同じことができるようになります。

Office xlsx — 表計算ファイル

anthropics/skills@xlsx

.xlsx / .xlsm / .csv / .tsv の読み書き、数式・書式の設定、グラフ作成、崩れた表データの整形まで扱います。

想定利用方法「計測結果のエクスポート CSV を読んで、ウェハ別の RMSE をまとめた Excel を作って。半径150mm以上の点は除外して、シートは工程ごとに分けて」

Office docx — Word文書

anthropics/skills@docx

目次・見出し・ページ番号を持つ体裁の整った Word 文書の作成と編集。既存 .docx からの抽出や差し替えにも対応します。

想定利用方法「この design.md をもとに、社内提出用の Word 版を作って。目次と見出し番号を付けて、図は SVG から貼り込んで」

Office pptx — PowerPoint

anthropics/skills@pptx

スライドの新規作成、既存 .pptx の読み取り・編集、テンプレート（.potx）やノートの扱い。

想定利用方法「先週作った Transformer 構成図の PPTX を読んで、スライド2の図だけを差し替えて。他のページはそのまま」
✅まとめて入れられます

この3つは同じリポジトリにあるので、1コマンドで同時に導入できます（導入手順は8章）。

3. MATLAB — MathWorks 公式

開発方針で「実現可能性を検討する順番の1位」が MATLAB であることを踏まえると、この発見はかなり大きいはずです。MathWorks 自身が公開しているスキル集で、140件以上が含まれています。

⚠️まとめて入れないこと

航空宇宙・自動運転・PCB設計・無線通信など、使わない分野のスキルも大量に含まれます。全部入れると一覧が埋まってしまうので、必要なものだけを --skill で個別に指定してください。

スキル名用途と、効きそうな理由

4. Power BI / Fabric

Microsoft 公式の skills-for-fabric には、Power BI に直接効くスキルが揃っています。TMDL を手で書いている現状と噛み合います。

Power BI セマンティックモデルの作成

microsoft/skills-for-fabric@semantic-model-authoring

モデル定義の作成を支援します。TMDL を編集する作業そのものが対象です。

想定利用方法「litho-overlay の SemanticModel に、DimProcess テーブルを DirectQuery で追加したい。既存の TMDL の書き方（タブ字下げ、ref table の追加）に合わせて草案を作って」

Power BI レポートの設計・管理・計画

microsoft/skills-for-fabric@powerbi-report-design / powerbi-report-management / powerbi-report-planning / powerbi-report-authoring

レポートの見せ方の設計、運用管理、事前の計画づくり。4つに分かれているので必要なものだけ選べます。

想定利用方法「ウェハマップとトレンドを1画面に載せたい。スライサーは4つ。powerbi-report-design の観点でページ構成案を3つ出して」

Power BI モデリングと DAX 最適化

github/awesome-copilot@powerbi-modeling ／ @power-bi-dax-optimization

GitHub 公式リポジトリ収録。前者はモデル設計の指針、後者は DAX メジャーの改善に特化しています。

想定利用方法「このメジャーが DirectQuery で遅い。power-bi-dax-optimization の観点で書き換え案と、なぜ速くなるかを説明して」
💡Git 連携もあります

git-integration-operations-cli と deployment-pipelines-authoring-cli も同じリポジトリに含まれます。将来 Fabric 側の Git 連携やデプロイパイプラインを使う段階になったら候補になります。

5. データ分析・ノートブック

OpenAI公式 jupyter-notebook

openai/skills@jupyter-notebook

ノートブックの作成・編集を扱います。統計学習の教材や Kaggle 的な解析でノートブックを使う場面に向きます。

想定利用方法「Data Wrangler で出した前処理コードを起点に、ウェハ面内のばらつきを可視化するノートブックを作って。セルごとに何をしているか日本語のコメントを入れて」

CSV の中身確認は Data Wrangler と Rainbow CSV（VS Code 拡張）で足りています。pandas 系のスキルは複数見つかりましたが、役割が重なるため今回は推奨しません。

6. 開発フロー・品質

フロー systematic-debugging（体系的なデバッグ）

obra/superpowers@systematic-debugging

当てずっぽうで直すのではなく、仮説を立てて切り分ける手順を踏ませるスキルです。今回の調査で見つけたデバッグ系の中で最も採用されています。

想定利用方法「Windows 実機で PBIP が開けない。エラーは出るが原因が分からない。systematic-debugging の手順で切り分けて、次に試すことを1つずつ提示して」

フロー request-refactor-plan（整理方針の作成）

mattpocock/skills@request-refactor-plan

いきなり書き換えるのではなく、先に整理の計画を出させるスキルです。「変更前に方針を確認したい」という進め方と相性が良いです。

想定利用方法「regression-analyzer の app が1ファイルに集まりすぎている。request-refactor-plan で分割案を作って。実装はまだしないで」

OpenAI公式 gh-address-comments ／ gh-fix-ci

openai/skills@gh-address-comments ／ @gh-fix-ci

前者は PR に付いたレビュー指摘への対応、後者は CI の失敗対応。gh コマンドを使い、認証状態も先に確認してくれます。

想定利用方法「いまのブランチの PR に付いたコメントを読んで、対応方針を一覧にして。修正は承認してから」

Anthropic公式 doc-coauthoring（文書の共同執筆）

anthropics/skills@doc-coauthoring

設計文書・仕様・提案書を、いきなり書き始めずに構成から詰めていく進め方を提供します。requirements.md や design.md を書く場面に合います。

想定利用方法「新しい計測解析ツールの requirements.md を作りたい。doc-coauthoring の流れで、まず私に質問して要件を引き出してから書いて」
💡コードレビュー系は既に持っています

採用数の多いレビュー系スキルが複数ありましたが、自作の readable-code-review が既にあります。方針が競合するため追加は推奨しません。

「外部公開前に認証・公開範囲・機密情報の混入を確認する」という方針を、機械的に支援できます。

セキュリティ security-best-practices ／ security-threat-model

openai/skills@security-best-practices ／ @security-threat-model ／ @security-ownership-map

実装上の基本的な注意点の確認と、脅威モデルの整理。OpenAI 公式リポジトリに3種類が用意されています。

8. 導入手順

導入先は ~/.agents/skills/ になります。Archify のときと同様、既存の運用場所（~/.codex/skills）から見えるようにリンクを張る必要があります。

手順1：まず最優先の3つ（Office文書）

npx -y skills add anthropics/skills --skill xlsx,docx,pptx --agent codex --global --copy --yes

手順2：既存の運用場所から見えるようにする

Archify と同じ方法。1本ずつリンクを張れば Claude Code / Codex の両方から使えます
for s in xlsx docx pptx; do
  ln -s "$HOME/.agents/skills/$s" "$HOME/.codex/skills/$s"
done
ls -l "$HOME/.codex/skills"

手順3：必要になったら追加する

MATLAB は必要なスキルだけを指定（全部入れない）
npx -y skills add matlab/matlab-agentic-toolkit \
  --skill matlab-model-optics,matlab-fit-curve,matlab-solve-optimization,matlab-review-code \
  --agent codex --global --copy --yes

Power BI / Fabric
npx -y skills add microsoft/skills-for-fabric \
  --skill semantic-model-authoring,powerbi-report-design \
  --agent codex --global --copy --yes

✅試してから決められます

インストールせずに動きを確認したい場合は npx skills use <owner/repo>@<skill> --agent codex が使えます。Archify のときと同じやり方です。

9. 注意点と、見送った判断

🛑スキルはエージェントの全権限で動きます

インストール時に CLI 自身がこう警告します — 使う前に中身を確認すること、そしてスキルはエージェントと同じ権限で実行されること。第三者が書いた指示をエージェントが読んで従う仕組みである以上、発行元の確認は必須です。本レポートで公式リポジトリを中心に選んだのはこのためです。

見送ったもの と その理由
対象見送った理由
コードレビュー系スキル全般自作の readable-code-review と方針が競合する
pandas / CSV 系スキルData Wrangler と Rainbow CSV で足りている
PDF 系スキルすでに pdf スキルを持っている
日本語ライティング系スキル検索で見つかったものは採用数が2桁台と少なく、自作の document-antipattern-check の方が要件に合っている
技術文書テンプレート集（個人リポジトリ）スター15件と実績が乏しく、社内利用の判断材料として弱い
Figma 関連（openai/skills に多数）デザインツールを使う作業が見当たらない
⚠️ライセンスの確認が必要なもの
  • MathWorks の toolkit：ライセンス表記が標準形式ではありません（GitHub API では「NOASSERTION」）。業務利用の前にリポジトリの LICENSE を確認してください
  • anthropics/skills・openai/skills：API 上はライセンス欄が空でした。個々のスキルにライセンス表記がある場合があります（Archify は MIT と明記されていました）
💡入れすぎない

スキルは増えるほど、エージェントが「どれを使うか」を判断する負担が増えます。まず Office文書の3つだけ入れて、しばらく使ってから次を足すのが確実です。Archify のときと同じ進め方です。
