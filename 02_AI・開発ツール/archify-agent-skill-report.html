「Archify」という名前は他にもあります。VS Code Marketplace には無関係な同名拡張が2件（インストール数191件・22件）存在し、ブラウザ上でWebアプリ構成を見る別サービスもあります。本レポートが扱うのは、AIエージェント用スキルの Archify（tt-a1i/archify）です。

0. Archifyとは（3分で把握）

ひとことで言うと、「AIに構成図を描かせるとき、デタラメな線を引かせないための仕組み」です。

観点内容
何をするかシステムの説明文（またはリポジトリの中身）から、構成図をHTMLファイルとして生成する
誰が使うかClaude Code / Codex CLI などのAIエージェントを使っている人
どこで動くか手元のPC。Node.js製のプログラムがローカルで図を組み立てる
出てくるもの1ファイルで完結するHTML（外部依存なし）。PNG / SVG / WebM 等への書き出しも可能
他と何が違うか図を出す前に機械的な検証を通す。検証に落ちたら理由が機械可読な形で返る

1. 何を解決する道具か

AIに「この構成を図にして」と頼むと、それらしい図はすぐ出てきます。問題はその図が正しいかどうかを誰も確かめていないことです。

従来のやり方との比較
観点AIにMermaid等を書かせるArchify
生成の仕方AIが図の記法を直接書くAIは型付きJSONを書き、図は決まった手順で組み立てられる
存在しない接続もっともらしく描かれても気づけないスキーマと検証で弾かれる
線の重なり・ラベル被り目視で直すしかないレイアウトと経路のチェック項目がある
失敗したとき「なんかおかしい」で終わる規則コード・対象・計測値・使える修正手段がJSONで返る
再現性頼むたびに違う図になる同じJSONからは同じ図が出る（決定的）
💡核心

Archifyの価値は「きれいな図が出ること」ではなく、AIと図の間に検証を挟んで、AIの創作を機械的に止めることにあります。図の見栄えは結果として付いてくるものです。

2. 仕組み — 4段階の流れ

1
説明する（人間）
「この構成を図にして」と会話で頼む。リポジトリを見せて実コードから起こさせることもできる。貼り付けたMermaid（flowchart / sequenceDiagram / stateDiagram）を入力にすることもできる
▼
2
型付きJSONを書く（AI）
図そのものではなく、中間表現（IR）となるJSONを生成する。図の種類ごとにスキーマが決まっており、自由に書けない
▼
3
検証する（Archify）
スキーマ・レイアウト・描画・経路・ラベル間隔をチェック。落ちたら図は出ない。理由が機械可読なJSONで返り、AIがそれを見て直す
▼
4
組み立てて渡す（Archify）
検証を通ったJSONから、1ファイル完結のHTMLを決定的に生成。ダーク／ライト切替、任意でアニメーション付き
✅ここが効いている

AIが触るのは段階2のJSONだけで、図の描画そのものには関与しません。だから「AIが線を1本でっち上げる」ことが構造的に起きにくくなっています。

3. 作れる5種類の図

種類は5つに限定されています。何でも描ける汎用ツールではなく、用途を絞ることで検証を可能にしている設計です。

architecture（構成図）

コンポーネント、サービス、ストレージ、信頼境界

用途：システム全体像、クラウド構成、ネットワーク構成

workflow（業務・処理フロー）

承認ゲート、ツール呼び出し、手順書、CI/CD

用途：開発フロー、リリース手順、承認プロセス

sequence（シーケンス図）

API呼び出しの順序、キャッシュのフォールバック、認証の流れ

用途：処理の時系列、システム間のやり取り

dataflow（データフロー）

パイプライン、系統（リネージ）、個人情報の流れ、利用先

用途：ETL、データの出どころと行き先の整理

lifecycle（状態遷移）

状態、リトライ、待機、終了状態

用途：ジョブの状態管理、リトライ設計

4. 検証ゲート — このツールの本質

成果物を渡す前に、次の観点で検査されます。

検証の5観点
検証見ているもの
スキーマ検証JSONが図の種類ごとの型定義に沿っているか
レイアウト検証要素の配置が破綻していないか
HTML/SVG描画検証実際に描画できるか
経路検証線の引き回しが成立しているか
ラベルと経路の間隔検証文字が線に被って読めなくなっていないか

品質プロファイル：basic と showcase の違い

⚠️「検証が通った」の意味は2種類ある
  • 基本検証＝チェック項目 4件 のみ。これは showcase 合格ではありません
  • showcase 合格＝チェック項目 9件すべてで、構成エラー0件・警告0件

スキル定義では、利用者が明示的に密な図を求めない限り showcase を既定にするよう指示されています。受け取った図の品質を確かめたいときは、9項目の検証結果が出ているかを見てください。

検証に落ちたときの挙動

失敗すると、次の情報を含む機械可読なJSONが返ります。AIはこれを読んで修正します。

項目内容
規則コードどの検査に落ちたか
対象（subject）どのノード・どの線が問題か
証拠（evidence）実測値。「何ピクセル足りない」など
使える修正（supportedFixes）認められている直し方の選択肢

スキル定義には、2回続けて改善しなければ修正を打ち切り、未解決の内容を正直に報告するという指示も含まれています。無限に直そうとして時間を浪費しない作りです。

5. 導入手順

5-1 前提の確認（この環境では確認済み）

前提要件この環境の実測
Node.js^22.19.0 または >=24.0.0✅ v24.14.1（条件を満たす）
npm / npx必要✅ npm 11.11.0 ／ npx あり
スキルの置き場所エージェントごとのskillsフォルダ✅ ~/.claude/skills（9件）と ~/.codex/skills（8件）が既に運用中
Archify自体—❌ 未導入
リポジトリ不要説明文だけでも図は作れる

5-2 インストール

用途に応じて3通りあります。

A. まず試すだけ（インストールしない・おすすめ）
npx skills use tt-a1i/archify@archify --agent codex

B. 全体に導入する（推奨される標準手順）
npx skills add tt-a1i/archify -g

C. Cursor向けに対話なしで導入する
npx -y skills add tt-a1i/archify --skill archify --agent cursor --global --copy --yes

✅導入後の動作確認

スキルのフォルダに入って次を実行すると、環境の点検とサンプル生成ができます。demo は実際のHTMLを出力するので、成果物の雰囲気を最初に掴めます。

node bin/archify.mjs doctor
node bin/archify.mjs demo /tmp/archify-demo

💡Claude Code と Codex の両方に入れる場合

この環境は ~/.claude/skills と ~/.codex/skills を同じ内容で運用しています。Archifyも両方に入れるか、片方だけにするかを最初に決めて揃えておくと、後で「片方では図が作れない」という混乱を避けられます。

6. 使い方

6-1 基本は「会話で頼む」だけ

導入後は、エージェントとの会話でそのまま依頼します。コマンドを覚える必要はありません。

依頼の例
litho-overlay-dashboard の構成図を作って。
Vertica から DirectQuery でデータを取り、Power BI のセマンティックモデルを
経由してレポートに表示される流れが分かるようにしてほしい。

エージェントが図の種類を選び、JSONを書き、検証し、HTMLを出力します。うまくいかない場合は検証結果をもとに自動で修正を試みます。

6-2 CLIコマンド（自分で確認したいとき）

主なコマンド
コマンド用途
doctor環境の点検。動かないときの一次確認
demoサンプル一式を出力。最初に雰囲気を掴む
guide説明文を渡して、作り方の案内を得る
validate検証だけ行う。図は出力しない
previewHTMLを生成して確認する
deliver最終的な受け渡し。これが合格判定を兼ねる
compare2つの構成図を比較し、差分を図にする
brands製品ロゴ・ブランド表記を検索する
検証と受け渡しの実行例（showcase品質）
node bin/archify.mjs validate workflow examples/agent-tool-call.workflow.json --quality showcase --json

node bin/archify.mjs deliver workflow examples/agent-tool-call.workflow.json /tmp/workflow.html --quality showcase --open --json

⚠️「終了コードが0以外＝失敗」

deliver が失敗した場合、前回の出力ファイルがそのまま残ります。古い成功時のファイルを見て「できた」と勘違いしやすいので、必ず実行結果の成否を確認してください。

6-3 出力できる形式

形式用途
HTML（1ファイル完結）既定の出力。外部ファイルに依存しないので、そのまま配布・埋め込みできる
PNG / SVG資料への貼り付け。SVGはGitでの差分管理にも向く
WebM動きのある説明用
シェアカード（1200×630 PNG）READMEやリリースノートの見出し画像

7. この環境での活用案

手元のリポジトリに当てはめると、次のような使い道が考えられます。

図の種類題材効果
architecturelitho-overlay-dashboard の Vertica DirectQuery 構成接続先・複合モデル・レポートの関係が1枚で伝わる。設計文書に添付できる
workflowブランチ → 実装 → PR → 確認 → マージ の開発フロー運用ルールを図で共有できる
dataflow計測CSV → 前処理 → Zernike分解 → ダッシュボードデータの出どころと加工段階が追える。引き継ぎ資料に効く
sequencePython API と社内Webアプリのやり取り処理順序の認識合わせ
lifecyclePower BI データセットの更新状態（成功／失敗／リトライ）異常時の扱いを明示できる
✅既存のHTML手順書と相性が良い

出力が1ファイル完結のHTMLなので、これまで作ってきた手順書やレポートにそのまま組み込めます。SVGで書き出せばMarkdownからも参照でき、Gitでの差分管理も可能です。導入済みの Draw.io 拡張が「自分で描く図」なのに対し、Archifyは「説明から起こす図」で、役割が重なりません。

8. 限界と注意点

🛑「検証を通った」＝「事実と一致する」ではない

これが最も重要な注意点です。Archifyの検証が保証するのは、図として成立していること（スキーマ・レイアウト・描画・経路）であって、描かれた内容が実際のシステムと合っているかではありません。元の説明が間違っていれば、検証を通った美しい間違いが出てきます。図の内容は人間が確認してください。

⚠️機密情報の扱い

Archify本体は手元で動きますが、図の元になる説明はAIエージェントを経由します。社内システムの構成図を作るということは、その構成をAIに説明することと同じです。既存のAI利用と同じ基準で判断してください。なお生成された図（HTML/PNG）はローカルに保存され、自動でどこかに公開されることはありません。

設計上、対応していないこと
対象外意味
汎用の自動レイアウトどんな図でも自動で整えてくれるわけではない。5種類の型に沿って作る
Mermaidの自動解析貼り付けたMermaidを入力にはできるが、既存図を自動で読み込む機能ではない
ホスティング（共有URL）ファイルを配る方式。共有の仕組みは自前で用意する
画面上での編集（WYSIWYG）マウスで図を直す機能はない。JSONを直して作り直す

その他、把握しておくとよい点

  • 主要ノードは12個までが推奨です。大きなシステムは分割して複数枚にする前提です
  • 更新チェックは通知のみで、勝手に更新はされません。スキル定義に「導入済みのバージョンは変更しない」「利用者が判断する」と明記されています
  • 公開Issueは118件あり、活発に開発中です（最終更新：2026-09-06）。仕様変更の可能性を織り込んでください
  • この種のツールは紹介記事が多く、GitHubスター数などの数値が記事ごとに大きく食い違っています。数字は公式リポジトリで直接確認するのが確実です（本レポートの数値はAPIから取得したものです）

9. 導入判断のまとめ

観点評価
導入の手間小さい。前提のNode環境は条件を満たしており、コマンド1つで試せる
既存環境との衝突なし。スキルの追加のみで、VS Code拡張やPython環境に影響しない
効果が出やすい場面設計文書・引き継ぎ資料・手順書に図が要るとき
効果が薄い場面図を1枚だけ手早く描きたいとき（Draw.ioの方が速い）
リスク図の内容の正しさは保証されない。機密構成をAIに説明する点の判断が必要
✅おすすめの進め方
  1. まずインストールせずに試す（5-2のA）
  2. demo でサンプルを出力し、成果物の質を自分の目で確認する
  3. 機密性の低い題材（例：開発フローの図）で1枚作ってみる
  4. 実務で使えると判断したら、Claude Code と Codex のどちらに入れるかを決めて導入する
