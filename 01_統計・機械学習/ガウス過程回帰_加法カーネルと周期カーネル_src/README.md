# ガウス過程回帰の解説動画（加法カーネル・周期カーネル）— 生成元

ガウス過程回帰（GPR）を基礎から発展まで解説する動画 `../ガウス過程回帰_加法カーネルと周期カーネル.mp4`（本編）と、その想定質問に答える動画 `../ガウス過程回帰_想定質問と回答.mp4` の生成元です。
本編は、理論（式）と図解（グラフ）を交互に進めます。冒頭で全体像と多変量正規分布、前半で RBF と Matérn カーネル（なめらかさ ν、スペクトル密度、ν → ∞ で RBF になる理由）、後半で加法カーネル（質的変数の扱いを含む）と周期カーネルの具体的な計算を扱います。
想定質問の動画は、加法カーネルの部品が事後に相関する理由とその影響を中心に、よくある質問6つに答えます。

- 1920×1080、30fps、H.264、字幕と読み上げ音声つき（Mac の声 Kyoko、AAC 24kHz・32kbps）。本編は約35分、想定質問は約7分
- 作り方はスキル「動く構成図（animated-arch-diagram）」の録画方式を使っています。時刻 t を入れると必ず同じ絵が出るページを作り、ヘッドレス Chrome で1コマずつ撮って ffmpeg で MP4 にします。

## 本編の構成（40場面）

| 章 | 理論 | 図解 |
|---|---|---|
| はじめに | 題名と目次 | |
| 1 全体像 | | 事前分布 → データで条件づける → 予測平均と帯（各段階がどの章か） |
| 1 多変量正規分布 | 平均ベクトルと共分散行列、相関係数、周辺分布・和・条件付き分布、数値例（ρ = 0.8） | 相関を変えたときの点の広がり、f₁ = 1 と分かったときの f₂ の分布 |
| 1 ガウス過程とは | GP の定義、有限個の点は多変量正規分布 | 2点の相関（楕円）→ 点を増やすと関数になる |
| 2 RBF カーネル | 2点の距離 r の定義（数直線）、式、σ_f² と ℓ、数値の表、3×3 の行列 | 6×6 行列を埋める、ℓ を変えたときの行列とサンプル |
| 2 Matérn カーネル | 一般式、ν = 1/2・3/2・5/2 の式、数値の表、微分できる回数（ν > m） | ν ごとのカーネルの形とサンプル、拡大して微分できるかを見る |
| 2 スペクトル密度 | カーネル ＝ 波 cos(ωr) の重ね合わせ、p(ω) の意味（ボホナーの定理）、RBF の p(ω) | 波を ω の小さい方から足してカーネルを作る（RBF と ν = 1/2） |
| 2 ν → ∞ で RBF | t 分布 → 正規分布、裾の重さと微分の回数、RBF との差（約 0.23/ν）、ν ≥ 7/2 は RBF とほぼ同じ | ν を大きくしていったときのカーネル・スペクトル・サンプル |
| 3 予測の式 | 条件付き正規分布、μ*・σ*²・α | データを1点ずつ足す |
| 3 3点で計算 | K+σ²I、α、k*、μ*、σ*² を数値で | 予測平均 ＝ α_i k(x, x_i) の山の重ね合わせ |
| 4 周辺尤度 | 当てはまり・複雑さの罰則・最大化 | ℓ を動かしたときの2つの項と予測 |
| 5 組み合わせ規則 | 和と積は正定値、和＝独立な部品の足し算 | 4種類のカーネルの形とサンプル |
| 6 周期カーネル | 円への写像からの導出 | x 軸を円柱に巻きつける（らせん → 円）、弦の長さと k |
| 6 数値で計算 | r ごとの表、ℓ の影響、行が重なり det K = 0 | 行列の縞、サンプル、外挿（RBF との比較） |
| 7 加法カーネル① | 独立の意味と交差項が 0 になる理由、共分散の展開、トレンド＋季節の数値表 | K₁ + K₂ = K、サンプルの足し算 |
| 7 予測の分解 | 共通の α、部品ごとの平均・分散・事後共分散 | トレンドと季節への分解、RBF だけとの比較 |
| 8 加法カーネル② | 入力次元ごとの和と積、数値の比較 | 十字形と丸、格子柄のサンプル、L 字データからの予測 |
| 9 加法カーネル③ 質的変数 | 一致・交換可能・共領域化のカーネル、one-hot＋RBF ＝ 交換可能 | 加法・積・共通＋個別の行列（ブロック）とサンプル |
| 9 ずれの推定 | ずれ ＝ σ_c² × α の合計、縮み方（変量効果）、σ_c² → ∞ で固定効果 | データの少ないカテゴリの予測（無視・別々・加法）とずれの推定 |
| 10 積カーネル | 局所周期、和との使い分け | 周期だけ・和・積のサンプル |

## 実行方法

必要なもの: Node.js（24 で確認）、ffmpeg、Google Chrome（ヘッドレスで使う）。

```bash
npm install
node tools/render.mjs info                    # 尺と場面の時刻表
node tools/render.mjs sheet 8 --scene 6V      # 1場面を8コマ並べた確認画像（out/sheet-6V.png）
node tools/render.mjs stills 660,1104         # 指定した秒の原寸画像（out/still-<秒>.png）
node tools/render.mjs video gpr --workers 4   # 書き出し（out/gpr.mp4 と out/gpr-poster.png）
node tools/render.mjs serve                   # ブラウザで確認するための URL を表示
```

音声つきの動画は、次の順で作ります（声の長さで字幕の時間が変わるため、映像は声を作ったあとに書き出す）。

```bash
node tools/render.mjs voice                   # 原稿を音声にする（narration/clips/）、長さを narration/seconds.js に書く
caffeinate -i node tools/render.mjs video gpr --workers 4   # 新しい時間割で映像を書き出す
node tools/render.mjs mux gpr                 # 音声を字幕の時刻に並べて重ねる（out/gpr-voice.mp4）
```

想定質問の動画は、同じ手順に `--page faq.html` を付けます（声の長さは narration/seconds-faq.js に書く）。

```bash
node tools/render.mjs voice --page faq.html
caffeinate -i node tools/render.mjs video faq --page faq.html --workers 4
node tools/render.mjs mux faq --page faq.html  # out/faq-voice.mp4
```

声は `--voice`、速さは `--rate`（語/分。既定 220、Mac の標準は 180）で変えられます。
動画全体の速さは `js/engine.js` の `PACE`（既定 1.1）で決まります。時間割と場面の動きは速さ 1 の秒で組み、動画では PACE 倍で進めます。声の長さは PACE 倍して時間割に入れるので、`--rate` と `PACE` のどちらを変えても声と字幕はずれません。`PACE` 1.1 に合わせて、声も `--rate 220` で、もとの 200 の約1.1倍速くしています。
高音質の声（Kyoko や Otoya の「拡張」「プレミアム」）を使うときは、システム設定の［アクセシビリティ］→［読み上げコンテンツ］→［システムの声］→［声を管理］で追加してから、`say -v '?'` に出る名前を `--voice` に渡し、上の3つをやり直します。

ブラウザで見るときは `serve` が表示する URL を開きます（KaTeX のフォントは `file://` では読めないため）。
`?scene=6V` でその場面から、`?t=660` でその時刻に止めて表示します。再生中はスペースで一時停止、←→ で5秒戻る・進む、[ ] で前・次の場面です。

## 注意事項

- 認証情報や環境変数は使いません。
- `out/`（確認画像と書き出し途中のファイル）、`narration/clips/`（音声ファイル）、`node_modules/` は Git に含めません。
- 読み上げは Mac の `say` コマンドを使うため、`voice` は Mac でだけ動きます。
- 書き出しは Mac（8コア、4並列）で、本編が約26分（63,189コマ。音声つき MP4 は約50MB）、想定質問が約5分（13,182コマ、約10MB）かかりました。本編が GitHub の警告（50MB）を超えないよう、映像は CRF 26・preset slow、音声は 24kHz・32kbps（声だけなので足りる）で書き出しています。これ以上長くするなら、画質か音声をもう一段下げる必要があります。`--workers` で並列の数を変えられます。
- `say` がまれに止まったまま返らないことがあるため、`voice` は1本60秒で打ち切って作り直します（3回まで）。
- 書き出しの途中でスリープすると撮影が止まることがあるため、Mac では `caffeinate -i node tools/render.mjs video gpr --workers 4` のように実行します。
