# 階層ベイズモデル（YouTube 向けの解説動画）— 生成元

階層ベイズモデルの考え方を、約22分で解説する動画 `../階層ベイズモデル_データの少ないグループを全体の情報で補う.mp4` の生成元です。
式で確かめる「理論」と、図で確かめる「図解」を交互に進めます。

- 1920×1080、30fps、H.264、字幕と読み上げ音声つき（VOICEVOX:四国めたん、AAC 96kbps・モノラル）、21分57秒
- YouTube 向けの動画なので、Remotion（React で動画を作る道具）で作っています
- 図の数値は、説明用に乱数で作った合成データ（8校のテストの点数）を、実際に階層ベイズモデルで推定した結果です（実測のデータではありません）

## 読み上げ音声のクレジット（必ず書く）

読み上げ音声には、無料の音声合成ソフト VOICEVOX の「四国めたん」を使っています。
利用規約により、動画を公開するときはクレジットの表記が必要です。動画の最後の画面には入れてあります。**YouTube の説明欄にも、次の1行を書いてください。**

```
VOICEVOX:四国めたん
```

規約は変わることがあるので、公開の前に、VOICEVOX の利用規約（https://voicevox.hiroshiba.jp/term/）と、四国めたんの規約（https://zunko.jp/con_ongen_kiyaku.html）を確認してください。

## 例の設定

- **データ**：8校（A〜H）の生徒の点数。受験者数は 15・30・3・8・40・20・4・12 人（計132人）
- **作り方**：学校の実力 θ を平均65・標準偏差6の正規分布から選び、生徒の点数を平均 θ・標準偏差15の正規分布から選んで、整数に丸め、0〜100点に収めた。乱数の種 145
- **モデル**：点数 ~ N(θ_j, σ²)、θ_j ~ N(μ, τ²)。事前分布は μ が一様、τ が0以上で一様、σ は log σ が一様
- **計算**：ギブスサンプリング、6000回×4本、はじめの1000回は捨てる（標本 2万個）。乱数の種 7
- **本当の値との比較**：同じ設定でデータを500回作り直し、毎回1本・3000回（はじめの600回は捨てる）で推定した
- **違いが小さい・大きい場合**：本当の τ を 1.5 と 12 にして、それぞれデータを作り直した（乱数の種 301・303）

表示用のデータの乱数の種（145）は、`node tools/make-data.mjs --search` で候補を出し、「人数の少ない C 校が、平均点では1位なのに本当の実力は1位でない」「G 校が最下位」という、説明に向いた例を選びました。
このため、1回分の結果（RMSE など）は都合のよい例になっている可能性があります。偏りのない比較として、500回作り直した平均もあわせて示しています。

## 計算で分かったこと

- 学校の中のばらつき σ の推定値（学校ごとの平均からのずれをまとめたもの）は 13.58、全員の平均は 60.6
- 事後分布：μ の平均 61.3（95% 区間 54.4〜68.2）、τ の中央値 7.2（95% 区間 3.4〜17.2）、σ の中央値 13.6。R̂ は μ・τ とも 1.00
- 縮約：C 校（3人）は平均点 72.3 → 推定値 66.4、G 校（4人）は 49.5 → 55.1、E 校（40人）は 52.1 → 53.0
- τ・σ・μ を事後分布の中央値に固定した計算では、縮約の強さ B は C 校で約0.54、E 校で約0.08。B が 0.5 になる人数は σ²/τ² ≈ 3.6人
- 1位である確率：B 校 54%、C 校 31%、H 校 10%（本当の1位は B 校、69.9）
- 95% 区間の幅：C 校は別々の推定 30.7 → 階層ベイズ 23.6、E 校は 8.4 → 8.6
- 表示用のデータでの RMSE：別々 6.2、まとめて 5.8、階層ベイズ 4.0
- 500回作り直した RMSE：別々 5.1、まとめて 6.0、階層ベイズ 3.9。階層ベイズのほうが別々の推定より誤差が小さかったのは 80%。学校ごとでは C 校 9.0 → 5.6、G 校 7.2 → 5.2 と大きく減り、E 校は 2.35 → 2.33 でほぼ同じ
- 違いが小さい場合（本当の τ 1.5）は τ の中央値 1.8 で強く縮約し、大きい場合（本当の τ 12）は τ の中央値 11.0 で、推定値は平均点からあまり動かなかった

## 実行方法

必要なもの: Node.js（24 で確認）、ffmpeg、VOICEVOX（アプリ 0.26.2・エンジン 0.26.1 で確認。https://voicevox.hiroshiba.jp/ から入手する）。

```bash
npm install
```

VOICEVOX を起動してから（アプリを開くだけでよい。このPCの中の `http://127.0.0.1:50021` で読み上げの受付が始まる）、次を実行します。

```bash
npm run data        # 数値を計算して src/data.json に書く（約3秒）
npm run voice       # 四国めたんの音声（public/voice/）と時刻表（src/timeline.json）を作る
npm run dev         # Remotion Studio でプレビューする
node tools/voice.mjs --kana     # VOICEVOX の読み方（カナ）を表示する。読み間違いの点検に使う
node tools/stills.mjs 4K 6V     # 指定した場面の確認画像を out/stills/ に書く
npx remotion render HierarchicalBayes out/hierarchical-bayes.mp4   # MP4 に書き出す
```

書き出したままだと音声のデータが大きいので、音声だけ軽くしてから、親フォルダに置きます（映像は変えません）。VOICEVOX の音は小さめなので、ここで音量を 5dB 上げ、音が割れないように上限をかけています。

```bash
ffmpeg -i out/hierarchical-bayes.mp4 -c:v copy -af "volume=5dB,alimiter=limit=0.7:level=false" -c:a aac -b:a 96k -ac 1 -movflags +faststart ../階層ベイズモデル_データの少ないグループを全体の情報で補う.mp4
```

VOICEVOX がないときに画面だけ確かめたい場合は、`node tools/voice.mjs --draft` で、Mac の声（Kyoko）の下書き音声が作れます（完成版には使いません）。

## 注意

- 読み上げの音声（`public/voice/`）はリポジトリに含めていません。はじめに `npm run voice` を実行してください
- 字幕を直したら、`npm run voice` で音声と時刻表を作り直してから書き出します（場面の長さは音声の長さで決まります）
- 字幕の数値は手で書いています。データを作り直したら、`npm run data` の表示と見比べて `src/script.ts` も直します
- 第4章の計算（C 校で 66.3）は τ・σ・μ を中央値に固定した値、第6章の推定値（C 校で 66.4）は MCMC の標本の平均で、計算のしかたが違うため少しずれます
- 読み上げの読み方は、VOICEVOX が出すカナ（`--kana`）で点検しましたが、耳では確かめていません。話す速さは、これまでの動画と同じ、標準の 0.95 倍です
- 読み上げは、このPCの中の VOICEVOX だけで行います。外部のサービスへ原稿を送りません
- 認証情報は使っていません。環境変数の設定は不要です
- Remotion は、個人と小規模な組織は無料で使えます。会社で使う場合は、ライセンスの条件（https://www.remotion.dev/docs/license）を確認してください
